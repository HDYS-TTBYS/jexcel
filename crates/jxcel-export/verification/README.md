# Excel・Word・スマートフォンでの確認

jxcel の書き出し（xlsx / docx）と LAN フォームは、**LibreOffice・`python-docx`・`openpyxl`・Chromium** では確かめてある。
**Excel・Word・スマートフォンの実機ブラウザ**だけは、開発環境に無いので確かめられていない。ここに、確かめるためのファイル一式の
作り方と、見てほしい点をまとめる。

## 1. ファイル一式を作る

```text
cargo run -p jxcel-export --example make_verification_set -- ./verify
```

`./verify` に 18 個のファイルができる（`*.out.docx|xlsx` が差し込み後、`*.out-empty.docx|xlsx` が 0 件の場合）。
サンプルデータは、明細が「ねじ（数 3・付属 a, b）」と「板（数 1・付属なし）」の 2 件。

テンプレートを作り直すとき（`verification/templates/*.xlsx`）は `python3 verification/make_templates.py 出力先 [--uno ポート]`。

## 2. Word（docx）で見る点

まず、**開いたときに「内容に問題が見つかりました。修復しますか？」と出ないこと**。出たら、そのファイル名を知らせてほしい。

| ファイル | 見る点 |
|---|---|
| `nested.out.docx` | 表の行のループが入れ子になっている（品名 ねじ → 付属 a, b / 板 → 付属なし）。小計・合計の行が崩れていない |
| `nested.out-empty.docx` | 0 件のとき、表が消えている（行のない表が残ると Word は開けない）。段落が空の表のまま残らない |
| `nested-table.out.docx` | 行の中の表（入れ子の表）の中のループ |
| `paragraphs.out.docx` | 表の外の段落のループ（`1. ねじ（3 個）`・`-a`・`-b`・`2. 板（1 個）`）。印だけの段落が空行として残らない |
| `cell-paragraphs.out.docx` | 表のセルの中の段落のループ。セルが空になっても、セルは最後が段落で終わっている（開ける） |
| `*.out-empty.docx` | 0 件で、ブロックごと消えている |

## 3. Excel（xlsx）で見る点

こちらも、**開いたときの修復の確認が出ないこと**が最初。その上で:

| ファイル | 見る点 |
|---|---|
| `nested.out.xlsx` | ループで増えた行に合わせて、合計の数式・結合セル・書式がずれている。数式が計算される |
| `chart-conditional-format-validation.out.xlsx` | 行が 2 件に増えた結果、**グラフが 4 点**（先頭・ねじ・板・末尾）になっている。条件付き書式（2 より大きいセルが黄色）が `B2:B5` に広がっている。データの入力規則が `B2:B5`。印刷範囲が 6 行目まで。名前付き範囲 `範囲` が `A2:B5` |
| `pivot.out.xlsx` | 集計シートのピボットテーブルが、**開いた直後に最新のデータ**（ねじ 3・板 1・先頭 1・末尾 5・合計 10）になる。「ピボットテーブルを更新してください」等のエラーが出ない。ブックの保存時に「元データを保存しない」設定になっているのは意図どおり（保存済みの古い記録を残さないため） |
| `pivot-in-loop-sheet.out.xlsx` | 元データと同じシートにあるピボットが、行が増えた分だけ下（11 行目）にずれ、元データの範囲が `A1:B5` に広がる |
| `three-d-sum.out.xlsx` | 集計シートの `A1` が `=SUM(A!B3,明細!B4,C!B3)`（= 3037）、`A2` が `=MAX(A!B1:B3,明細!B1:B4,C!B1:B3)`（= 3000） |
| `three-d-both-loop-sheets.out.xlsx` | `A1` が `=SUM(A:明細!B4)`（= 14）、`A2` が `=SUM(A:明細!B1:B4)`（= 222）、`A3` が `=SUM(A:C!B1)`（= 1200） |
| `x14-sparkline.out.xlsx` | `D1` のスパークラインが 4 本（100・3・1・7）、`D4`（末尾の行の隣）にもスパークライン。`E1` のドロップダウンの候補が 4 つ。`B1:B4` の条件付き書式 |
| `absolute-anchor.out.xlsx` | 2 つの図が、末尾の行に付いて下に動く／1〜3 行目に掛かっていた図が 1 行ぶん伸びる |
| `absolute-anchor-row-heights.out.xlsx` | 行の高さがばらばらで、非表示の行もあるシートでも、図が元の行に付いて動く（図 A は末尾の行の中、図 B は 2 行目の中ほどから最後の行の下まで） |
| `*.out-empty.xlsx` | 0 件でも空の行が 1 行残り、数式の参照が `#REF!` にならない |

## 4. スマートフォンで見る点（LAN フォーム）

```text
cargo run -p jxcel-app --example serve_forms
```

（アプリを起動せずに試せる。標準出力の `URL` を、スマートフォンのブラウザで開く。PC と同じネットワークであること。）
見る点:

- 日時の入力（`datetime-local`）で選んだ時刻が、そのまま（端末のオフセット付きで）保存される（標準出力の `ROWS` で確認）
- 送信後に「修正を送信」になり、内容を直して送ると**行が増えずに値が変わる**。ページを開き直すと前回の内容が入る
- 日本語のキーボード・入力候補で、氏名などが入力できる
- 合言葉つき（`serve_forms 0 himitsu-1234`）で、合言葉の入力欄が出る。間違えると拒否され、続けるとロックされる
- 回答者ごとの合言葉（`serve_forms 0 "" "" yamada-1,sato-22`）で、別のブラウザ（別の端末）から同じ合言葉で自分の回答を直せる
- プライベートブラウズでも送信できる（修正の鍵は覚えられず、開き直すと新しい回答になる）

## 5. 見つけた不具合の伝え方

ファイル名と、**Excel / Word のバージョン**、どこがどう違ったか（修復の確認が出たなら、その文言）を知らせてほしい。
可能なら、そのファイルを添付してもらえれば、同じ手順で再現して直せる。
