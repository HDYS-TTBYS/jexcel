# 使い方

## データ

1 つのファイル（`.jxcel`）に複数のシートがあり、シートには複数の**データスキーマ**（表）を置ける。列には型を付ける。型に合わない入力は拒否される。
スキーマはネストできる（オブジェクト・配列の列）。列の表示名は変えられるが、内部の ID は変わらないので、履歴の追跡は壊れない。

- 並べ替えは列ヘッダのクリック。表示だけの並べ替えで、ファイルの行の並びは変わらない。
- 日時は `2026-10-02T10:30:00+09:00` の形で、**書かれたままの時刻**を保つ。タイムゾーンの一括変換は、列の定義の「タイムゾーンを変換…」から。

## 履歴

保存のたびに内蔵 git へコミットされる。履歴パネルで、任意の 2 つの版の**構造的な差分**（シート・列・行・セル単位）を見られ、過去の版を読み込める。
読み込んだ版は未保存の状態になり、保存して初めて新しい版になる（履歴は消えない）。履歴は `.jxcel` に同梱されるので、ファイルを渡せば履歴も渡る。

## マクロ

`export default function (jx: Jxcel) { ... }` の形の TypeScript を書く。エディタ（Monaco）で補完と型検査が効く。サンプルマクロが同梱されている。

```ts
export default function (jx: Jxcel) {
  const rows = jx.sheet("シート1").schema("データ").rows();
  jx.sheet("シート1").schema("集計").add({ 列1: "合計", 列2: std.sum(rows.map(r => r["列2"])) });
}
```

マクロはファイルのコピーに対して動き、書き込みは検証を通ったときだけまとめて反映される（1 件でも不正なら全体を捨てる）。ファイル・ネットワークには触れない（メモリ 64MB・10 秒の上限）。

## 計算列

列に `export default function (row, jx) { return ... }` の式を持たせる。値は保存せず、表示のたびに計算する（履歴の差分に計算結果は出ない）。
式の失敗はそのセルだけが `#ERROR` になる。後ろの計算列は前の計算列の値を読める。

## 標準ライブラリ `std`

マクロにも計算列にも、import なしで使える。集計（`sum` `avg` `groupBy` `lookup` …）、日付（`std.date`：月末丸め・営業日・和暦・タイムゾーン変換）、`std.dec`（誤差のない 10 進数）、`std.text`（全角半角・かな）。
数値でない値は黙って 0 にせず例外になる。関数の一覧と説明は、エディタの補完とホバーで見られる。

## テンプレートの書き出し

xlsx / docx を「書き出し」パネルで登録し、表の行ごとに 1 ファイルを書き出す。テンプレートには `{{ 式 }}` と書く（列名が変数、`_no` は行番号、`std` も使える）。

- 行ループ: 表の行に `{{#each 付属}}` と書くと、その行が配列の要素の数だけ繰り返される。別の行の `{{/each}}` まで書くと、その間がまとめて繰り返される。入れ子にもできる。
- docx は表の外の段落・表のセルの中の段落もループできる。
- 既存のファイルは上書きしない（` (1)` が付く）。式の失敗は行ごとのエラーとして出る。1900 年より前の日付は文字列のままにして、注意として知らせる。

書き出す前に「プレビュー」で、差し込み欄とループの件数を確かめられる。

## LAN フォーム配信

表の列を選んで**フォーム**を作り、配信を始めると、同じネットワークのブラウザ用の URL（`/f/<乱数>`）が出る。回答は表に行として追加される（保存は自分で行う）。

- URL の乱数は配信のたびに作り直す。**合言葉**（任意）と**回答者ごとの合言葉**（1 人 1 件）を設定できる。失敗が続くと端末ごとにロックされる。
- 送信後の**修正**を許すか、何分以内かを設定できる。
- 「配信を続けたまま、別のファイルを開く…」で複数ファイルを同時に配信できる（裏のファイルは回答のたびに自動保存）。
